# 情绪维度

模型每次回复输出 `happiness`、`anger`、`hurt`、`sadness`、`loneliness`、`excitement` 的变化量，范围为 -10 到 10。后台应用敏感度与惯性后，将状态限制在 0 到 100，保存并带入下一次普通回复或自发发言。`tiredness` 由昼夜节律控制。

`sadness` 表示失落、难过或对悲伤经历的共情；`hurt` 表示受到伤害、委屈。两者独立，悲伤也不是愉悦的反值。提示词允许复杂情绪共存，要求基于实际情境变化，不把他人的遭遇写成自己的经历，也不因为安慰就在一轮内自动清空悲伤。

悲伤默认基线与初始值为 0，半衰期为 12 小时。与现有情绪一样，启动时根据距离上次互动的时长向基线恢复；运行期间主要由对话变化量改变，现有后台空闲更新只增加孤独，不承担持续的全情绪衰减。

旧状态文件首次由新版后端加载时会补齐缺少的默认字段并升级到版本 2，已有的情绪、基线、半衰期及性格参数保留。旧聊天里的情绪快照保持原样，不回填历史分数。

网页情绪面板显示“悲伤”，值达到 55 时可使用低饱和度的悲伤头像样式；“猜心情”互动也支持该状态。现有固定互动未配置悲伤变化量时按 0 处理。

## 情绪共鸣（mirror neurons）

这是伴侣架构中的情绪共鸣机制。模型在原有的同一次结构化回复中额外返回 `user_affect`，包括当前对话对象的愉悦、悲伤、兴奋强度（0–1）、判断置信度、来源类别和最新消息中的原文片段。不增加一次模型调用，也不靠情绪关键词直接计分。

只有 `source=current_user`、置信度至少 0.9，且依据确实是最新消息中引文和代码之外的非空原文时，才触发后台共鸣。本地模型在 0.8 左右仍出现情绪归属错误，因此默认采用更保守的阈值；模型输出的置信度不是经过统计校准的概率，隐含或复杂感受可能不触发。后台会遮蔽常见中英文引号、Markdown 引用、行内代码和代码块后核对依据，即使模型把引文误标为本人情绪，也不会产生该次共鸣。提示词区分当前真实感受、否定、过去的感受、他人的经历、引用、翻译、角色扮演和假设。模型识别仍可能出错；原文检查不能独立证明它理解正确，也可能保守地漏掉用引号表达的真实感受。

三个维度分别计算：`target = intensity × 80`；`raw = min(4, max(0, target − 当前值) × 0.12) × empathy × confidence`。`empathy` 沿用现有性格参数，默认 0.68，设为 0 时不产生数值共鸣。朝目标靠近而不是不断加固定分，使共鸣单独作用时不会把状态推到极端；目标以下只增加，不强行清空相反或既有的情绪。悲喜可以共存，愤怒、受伤和孤独不自动镜像。

后台还保守排除以常见条件句或他人叙述开头的依据片段，例如“如果……”“我朋友……”“My friend……”。这只验证依据的归属，不用情绪关键词计分；若同一句同时讲别人和自己，需要模型摘取本人感受的较窄片段。该检查不是完整的语言理解，复杂或未覆盖的表达仍有误判或漏判可能。

模型的 `emotion_delta` 表示角色自己的直接反应。与共鸣方向相同的增量取较大者，避免模型已计入共情时再次叠加；相反方向则相抵。合并后统一应用一次敏感度、惯性和 0–100 限制。当轮文字回复被要求体现自然共鸣，合并后的状态保存并带入下一轮。

普通网页和命令行对话都经过该机制。自发发言没有新用户消息，不再次应用共鸣；网页重新生成回复也不新增共鸣。重新生成沿用现有直接情绪反应处理，不回滚历史情绪。生成失败不应用共鸣。

聊天内部元数据记录 `user_affect`、`resonance_enabled`、`emotion_delta_proposed`、`emotion_delta_resonance`、`emotion_delta_combined` 和 `emotion_delta_applied`，便于追踪。推测出的情绪不会单独作为长期记忆入库，界面回复也不展示隐藏分数或诊断式标签。
