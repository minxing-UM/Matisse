# 自发想法：第一版

设置中的「主动陪伴」现在使用模型生成内容，取代原先的固定主动开口句式。
浏览器与命令行共用同一套调度、提示词和生成队列。

## 运行规则

- 服务运行期间，在清醒时段每隔随机 1–10 分钟生成一次。可以在设置中缩小间隔范围。
- 默认清醒时段为每天 06:00 到次日 02:00；可调整，开始与结束相同时表示全天。
- 总开关和静默时段同样生效。关闭、静默或非清醒期间不生成；恢复后重新安排时间，不补发错过的轮次。
- 随机时间在首次调度以及每次任务结束后确定，保存至 `repository/activities/thoughts.json`；重启后恢复。进程退出期间不会运行。
- 浏览器版本向最近打开的聊天写入想法。打开或新建另一段聊天需要等正在进行的生成完成，已经开始的发言仍属于原聊天。
- 后台没有开始任务时，用户请求优先；后台已经开始时让它先完成，然后按到达顺序处理等待的用户请求。
- 自发发言先作为 assistant 消息保存，随后用户消息才进入下一轮模型上下文。前端在等待答案时仍会刷新已完成的发言。
- 回复不是逐字流式播放。这里的「说完」指完整回复生成并保存完成。

## 提示词与长期方向

每次任务读取角色人格、当前情绪、时间、聊天上下文，以及开启记忆访问时的相关记忆。
「好奇、关系理解、自己的观点、兴趣、小步成长、当下感受」六类角度轮换，排除最近两次使用的角度。
最近五次自发发言进入避免重复的参考；与这些发言文本相似度达到 0.9 的结果不会再次发布，也不会应用该次情绪变化。
同时对比当前聊天最近三条助手回复，拦截相似度达到 0.82 的长文本近似复述和长段原文包含。可以围绕同一话题产生新联想，不要求强行换话题；这些文本规则不能可靠识别所有语义上的重复。

后台生成不再把历史作为待续答的 user/assistant 消息序列发送，而是将近期最多八条交流作为“已完成对话”的只读背景节选，当前自发任务放在最后。普通对话仍使用原消息角色。后台也不再带入“用户可能正在继续上个话题”的续聊提示，避免把旧问题重新当成当前请求。

角色应分享一个尚未表达过的新联想、新兴趣、新疑问或小打算。没有新内容时，`has_new_thought=false`、`reply=""` 可跳过本轮；不发布消息、不更新情绪、不更新最近发言，只正常安排下一次。旧模型输出未带该标志时沿用原行为。

生成端还会检测单条回复内部的异常连续重复，例如长串重复的“连着”。检测失败时丢弃整个草稿，添加重写要求、降低采样温度并最多重试一次；失败草稿不会保存或改变情绪。若两次都失败，后台跳过这次发言并正常安排下一次，不发布截断或拼接的半句。普通回复同样经过检查，持续失败则返回错误。

检查采用保守阈值，保留正常强调、笑声和代码块；它主要拦截明显的文本循环，不能修复所有错别字或保证内容质量。旧聊天中已存在的异常助手回复，以及最近想法中的异常文本，不再用作生成上下文示例；已有文件保留原样。困倦提示不再要求故意口误或自我纠正，主动发言最多使用 1024 个输出 token，并使用温和的重复惩罚。

默认长期方向兼顾关系与自我发展，在设置中可编辑。它为自发发言和普通回复提供背景方向；当前没有自主训练、自动修改代码或目标达成评估功能。
提示词要求把想法与真实经历区分开，避免虚构已完成的行动或角色成长。

后台任务使用额外的系统任务说明，不会把「你在想什么」写成真实用户消息。
结构化输出仍然包含回复、情绪变化和情绪标签。情绪经现有规则调整后保存，供下一次对话使用。
自发发言不伪造用户互动时间，也不单独排入长期记忆提取队列。

当前没有实现睡眠梦境、话题仅使用一次或三天内记忆过滤。后续加入的情绪共鸣机制见 [情绪文档](emotions.md)。

## 验证

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
node tests/test_frontend_thoughts.cjs
```

Python 测试使用隔离的临时数据目录与固定模型输出，覆盖排队顺序、情绪传递、调度恢复、静默与清醒时段、失败退避、重复过滤、配置验证和轮询幂等。
前端测试控制网络响应时序，检查排队问题不丢失、不重复，以及旧响应不会覆盖新对话。
这些测试不调用真实模型；内容质量需要通过实际聊天继续观察。
